# 空间文件夹 2.1.1：跨显示器布局技术说明

## 问题根因

2.1 把“当前显示器尺寸”同时当作“文件夹画布尺寸”。窗口切换显示器后，程序会按新屏幕宽高分别缩放所有坐标并立即保存；图标和文字的逻辑大小却不随坐标一起缩小。因此从大屏切到小屏时，图标中心点距离被压缩，图标互相靠拢甚至重叠，反复切换还会产生取整误差。

## 2.1.1 的三层结构

1. **逻辑画布**：每个文件夹保存一份固定尺寸和固定坐标，是布局数据的唯一基准。
2. **显示器状态**：只记录 App 当前位于哪种屏幕尺寸，不写入布局文件。
3. **视口变换**：根据逻辑画布、当前显示器和窗口宽度计算一个临时的统一缩放比例。

核心约束：显示器变化只能改变第三层，不能修改第一层。

## 缩放规则

视口比例取以下值的最小值，并且最大不超过 1：

- 窗口可用宽度 ÷ 逻辑画布宽度
- 当前显示器宽度 ÷ 逻辑画布宽度
- 当前显示器高度 ÷ 逻辑画布高度

同一个比例应用于整个画布，所以图标、字体、间距、框选区域和壁纸一起缩放。画布仍只允许纵向滚动，不产生横向滚动条。

## 数据迁移

- 布局格式从 v4 升级到 v5。
- v4 布局在明显更大的显示器首次打开时，以等比缩放加居中的方式迁移为大屏基准。
- 写入 v5 前先自动备份 v4 原文件。
- 如果旧版布局已经在小屏被压缩，用户可在大屏上选择“布局 → 将当前显示器设为基准画布”。该操作可撤销，并会创建布局备份。

## 不变量与验证

- 外接屏与内屏往返切换 10 次，导出的布局 JSON 必须逐字节相同。
- 在小屏重新启动 App，仍读取原有逻辑画布尺寸和坐标。
- 手动重设基准画布可撤销，撤销后尺寸和坐标同时恢复。
- 64 项 8×8 布局、文件重命名、根文件夹移动、布局损坏恢复等 2.1 行为继续通过回归测试。
