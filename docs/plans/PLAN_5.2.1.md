# 5.2.1 安全修复计划与验收

## 目标

在不改变 5.2 功能和资源模型的前提下，封住真实文件重命名及批量替换的路径越界风险，并防止打包脚本覆盖冻结产物。

## 范围

1. 重命名拒绝空名、点目录、路径分隔符和 NUL。
2. 重命名目标必须是当前空间的直接子项，来源也必须仍在当前空间第一层。
3. 整批复制、移动和替换必须在第一次真实文件变更前通过边界预检。
4. 打包目标已存在时直接失败，候选包支持独立后缀。
5. 不改动布局历史、压缩、多空间和工具栏功能。

## 验收结果

- 危险名称被拒绝，原文件、操作记录和授权目录外内容均不变。
- 包含越界目标的替换计划在任何项目入废纸篓前失败。
- 20/20 标准测试、80/80 完整自测、性能基线和严格 Release 构建通过。
- 候选 App 和 ZIP 签名复验通过，二次打包被防覆盖守卫拒绝。
- 5.1.0 与 5.2.0 冻结 ZIP 哈希未变。

## 发布状态

当前为构建号 5210 的可验收候选。用户验收后再生成无候选后缀的正式 App/ZIP，冻结并提交。
