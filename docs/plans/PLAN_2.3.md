# 空间文件夹 2.3 开发计划

计划执行日期：2026-07-16  
版本目标：修复普通窗口比例变化后画布下方出现空白的问题。  
已确认方案：**普通窗口锁定比例，全屏解除窗口约束。**

## 一、版本边界

- 2.2 是冻结版本，不直接修改、不覆盖现有安装包。
- 2.3 必须在独立开发分支或项目副本中进行。
- 本版本只处理窗口比例和画布显示问题。
- 不同时添加新的文件操作、右键菜单、拖拽或快捷键功能。
- 不改变文件的真实路径，不改变已经保存的画布逻辑坐标。

## 二、已确认的问题原因

当前画布按照基准桌面尺寸等比例缩放，但普通窗口可以被调整为任意宽高比例。缩放逻辑主要依据可用宽度；当窗口相对更高时，画布高度不足以填满窗口，画布下方会露出灰色窗口背景。

涉及范围：

- `Sources/SpatialFolder/CanvasViewport.swift`
- `Sources/SpatialFolder/ContentView.swift`
- `Sources/SpatialFolder/SpatialFolderApp.swift`
- 必要时增加一个很小的 AppKit 窗口访问或窗口约束组件

原则上不修改 `FolderCanvasModel.swift` 的文件操作和布局保存逻辑。

## 三、执行步骤

### 1. 保护 2.2 基线

1. 检查当前 Git 状态，保留所有现有修改，不执行清理或覆盖操作。
2. 确认能够还原 2.2 的源代码、安装包和版本说明。
3. 从确认后的 2.2 基线建立 `codex/2.3-window-aspect-fix` 开发分支，或建立独立项目副本。
4. 记录修改前的窗口截图和测试结果。

完成信号：2.3 的任何修改都可以单独撤销，不影响 2.2。

### 2. 建立问题复现基线

至少记录以下场景：

- 普通窗口接近最大化。
- 普通窗口宽而矮。
- 普通窗口窄而高。
- Mac 内置显示器。
- 外接显示器。
- 从普通窗口进入全屏，再退出全屏。

同时记录画布基准尺寸、窗口内容尺寸和缩放比例，确认底部空白的触发条件。

### 3. 实现普通窗口比例约束

目标行为：

- 普通窗口拖动宽度时，高度按比例联动。
- 普通窗口拖动高度时，宽度按比例联动。
- 使用“画布宽高比 + 顶部工具栏固定高度”计算窗口内容比例，不能简单锁定整个外框比例。
- 窗口不得超出当前显示器的可见区域。
- 保留现有最小窗口尺寸约束。
- 允许少量像素舍入，但不能露出明显灰色空白。
- 防御性地让窗口剩余背景与画布背景一致，避免 1～2 像素的系统舍入缝隙。

### 4. 全屏模式单独处理

- 进入全屏前解除普通窗口比例约束。
- 全屏状态使用显示器提供的完整可用区域。
- 全屏时画布保持等比例，不拉伸文件图标。
- 退出全屏后恢复普通窗口比例约束和退出前的合理窗口尺寸。
- 内外显示器比例不同的时候重新计算约束。

### 5. 保证空间坐标不被改变

本次只改变显示缩放和窗口尺寸，不重排文件：

- 不调用自动排列。
- 不重写已保存的图标坐标。
- 不改变图标大小、字体大小和吸附网格。
- 不因为窗口缩放产生新的布局历史记录。
- 切换全屏或显示器后，同一文件之间的空间关系保持不变。

### 6. 自动检查与人工回归

自动检查：

- 不同比例下的画布缩放计算。
- 最小窗口尺寸。
- 内置屏幕和外接屏幕尺寸切换。
- 普通窗口与全屏状态转换。
- 不产生负数尺寸、无穷值或越界缩放。

人工回归：

- 单击选择。
- 鼠标双向框选。
- 多选拖动。
- 双击打开文件和文件夹。
- 右键菜单。
- 新建文件夹、Word、Excel、PowerPoint。
- 从外部拖入文件。
- 锁定和解锁布局。
- 切换壁纸与系统外观。
- 关闭并重新打开 App 后图标位置不变。

### 7. 生成 2.3 测试版

1. 更新内部版本号为 `2.3.0`，明确标注测试版。
2. 先运行开发版和自检，不覆盖 `/Applications` 中现有的 2.2。
3. 生成独立的“空间文件夹 2.3 测试版.app”。
4. 由用户在内置显示器、外接显示器和全屏模式下验收。
5. 用户确认后，再冻结、提交 Git、更新说明并打包正式版本。

## 四、验收标准

必须全部满足：

- 普通窗口不能被调整成任意比例。
- 普通窗口底部不再出现截图中的大块灰色空白。
- 最大化和全屏显示正常，没有裁切、拉伸或额外空白。
- 进入和退出全屏后窗口尺寸正常。
- 内置屏幕与外接屏幕之间切换正常。
- 原有图标位置和相对空间关系不变。
- 多选、拖动、双击、右键和文件操作没有回归。
- 2.2 冻结版本和安装包保持不变。

## 五、停止条件

出现以下任一情况时，停止扩大修改范围并回到原因定位：

- 必须重写 `FolderCanvasModel` 才能继续。
- 图标坐标发生永久改变。
- 全屏修复导致普通窗口回归，或相反。
- 需要同时修改文件操作、复制粘贴或拖拽逻辑。
- 无法确认当前源代码对应冻结的 2.2 基线。
