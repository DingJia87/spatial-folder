# 空间文件夹 4.1 快捷唤醒维护说明

## 组件职责

- `GlobalShortcut.swift`：组合键模型、Carbon 独占注册、冲突回滚和偏好持久化。
- `AppVisibilityController.swift`：唯一主窗口的登记、显示、置顶和隐藏。
- `ShortcutSettingsView.swift`：组合键录制界面。
- `MenuBarContentView.swift`：不依赖主窗口可见性的备用入口。
- `FolderChangeMonitor.swift`：用文件级 FSEvents 捕获 Finder 标签扩展属性变化；无法启动时由模型保留根目录结构监听。
- `FolderCanvasModel.swift`：无论 FSEvents 是否可用，每秒对当前可见项目做轻量标签快照核对；筛选开启时每五秒补一次全目录核对。
- `FileIconCache.swift`：文件夹按首个 Finder 颜色标签生成着色图标缓存；普通文件保留系统原图标。

## 不变量

- 注册新快捷键时必须先成功取得新热键，再注销旧热键；失败时原热键继续可用。
- 不使用全局事件监听，因此不得新增辅助功能或输入监控权限依赖。
- 显示动作必须处理 App 隐藏、窗口最小化和窗口已关闭三种状态。
- 主画布必须是单实例；菜单栏和快捷键必须复用同一显隐控制器。
- 快捷唤醒不得修改真实文件、布局坐标或最近操作记录。
- 不能退回只监听根目录 vnode 的方案；子文件标签属于扩展属性变化，根目录 `.write` 不会触发。
- FSEvents 失败路径不能只核对标签；必须继续用 vnode 监听新增、删除和重命名，避免修复标签时破坏外部目录刷新。
- 标签核对必须常驻，不能以 FSEvents 成功启动为停用条件；部分卷或系统版本不会稳定报告标签扩展属性变化。
- 标签核对只比较标签数组，标签不变时不得发布新的 `items`，也不得重复布局计算。
- 文件夹标签变化必须同时使图标缓存失效并重绘图标本体；只出现颜色点不算完成。
- 标签写入必须按路径从模型重新取得最新项目，不能信任右键菜单或旧视图保存的标签快照。
- 系统菜单会把模板 SF Symbol 统一染色；标签圆点必须使用 `isTemplate = false` 的原色 `NSImage`，并进行真实菜单截图验收。
